每日 GitHub 热榜 → 微信公众号　自动化流程

一条链，从抓取到草稿，无人值守
① 定时触发 Linux crontab · 每天 08:00 · 云服务器常驻，无人登录也运行
▼
② run_daily.py　编排五步
1

采集榜单  fetch_and_rank.py

调 GitHub Search API 拉取最近新建的热门仓库（≈300 个）

读昨日快照 → 算每个项目的 Star 增量（首日无增量则回退按 Star 排序）

输出 data/daily/<日期>.md / .json，并保存今日快照

2

选榜·霸榜判定  select_daily.py

把当天收录的项目写入 data/tracking.db，算连续上榜天数

连续满 3 天的项目从第 4 天起转一行简报（不写正文、不配图）

空出的篇幅由榜单第 11 名起往后补，保证当天仍有 10 篇详写；连续满 5 天入深挖队列

输出 data/daily/<日期>.selected.json

3

生成文章  generate_article.py

读 selected.json，调 DeepSeek 按「逛逛GitHub」风格写中文文案

结构由代码固定、文案由模型生成 → 输出 data/articles/<日期>.md

4

优化标题  optimize_title.py

生成 6 个候选标题选优 → 就地改写文章首行

5

建草稿  wechat_publish.py

逐张配图下载 → uploadimg 换成微信托管地址

封面图 add_material；正文转成带内联样式的 HTML

draft/add 写入公众号草稿箱

▼
③ 公众号草稿箱 人工审核 → 手动发布（不自动群发）
另一条线：单项目深挖（每 72 小时一次，run_feature.sh 控时）
· feature_article.py 先消费深挖队列（连续上榜满 5 天的项目，按连续天数优先）
· 队列空了才去 GitHub Search 挑新项目 → 一次只加一个 → 入队后立即深挖 → 发草稿箱

运行环境依赖
· 环境变量（机器级 / /etc/github-trending.env）：DEEPSEEK_API_KEY · WECHAT_APPID · WECHAT_APPSECRET · GITHUB_TOKEN
· 运行机器的公网出口 IP 需加入公众号后台白名单
· 数据留痕：data/snapshots/（算增量基线）· data/tracking.db（上榜记录 + 深挖队列，运行态不入 git）· logs/run.log（追加日志）
